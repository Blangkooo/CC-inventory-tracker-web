InvenTrack API Documentation

Multi-Branch Inventory Tracker · REST API reference

Section 1: Authentication

No token required.

POST /api/auth/owner-login No auth
Body 
{ "email": "string", "password": "string" }
Response 
{ "user": {...}, "token": "string" }
Errors
  • 401 — wrong credentials
POST /api/auth/staff-login No auth
Body 
{ "pin": "string", "branch_id": "integer" }
Response 
{ "user": {...}, "token": "string", "branch": {...} }
Errors
  • 401 — wrong PIN or branch

Section 2: Protected Endpoints

Header required: Authorization: Bearer {token}

POST /api/auth/logout Bearer token
Response 
{ "message": "Logged out" }
GET /api/auth/me Bearer token
Response user object with branch
POST /api/transactions Bearer token
Body 
{ "product_id": int, "branch_id": int, "quantity": int, "client_uuid": "uuid" }
Response 201 
{ "transaction": {...}, "message": "...", "updated_stock": [...] }
Response 422 
{ "error": "Insufficient stock for X", "needed": "Xg", "available": "Xg" }
Note client_uuid must be unique — generate on mobile before syncing
GET /api/dashboard Bearer token
Response 
{ "total_branches": int, "total_products": int, "total_ingredients": int, "pending_alerts": int }
GET /api/branches/{branch_id}/stock Bearer token
Response 
[ { "ingredient": "string", "unit": "string", "current_quantity": float, "min_threshold": float, "status": "ok|low|out" } ]
POST /api/receipts/scan Bearer token
Body multipart/form-data 
{ "image": file (jpeg/png max 5MB), "branch_id": int }
Response 201 
{ "receipt": {...}, "ocr_text": "string", "parsed_amount": float|null, "reconciliation_status": "matched|mismatched|pending|unreadable", "matched_transaction": {...}|null }
GET /api/receipts?branch_id={id} Bearer token
Response paginated list of receipts
GET /api/receipts/summary?branch_id={id} Bearer token
Response 
{ "total_scanned": int, "matched": int, "mismatched": int, "pending": int, "unreadable": int }

Section 4: Notes for Frontend Team

  • Base URL: http://127.0.0.1:8000 (local) — update to production URL when deployed
  • All requests must include: Accept: application/json
  • All POST requests: Content-Type: application/json (except receipt scan: multipart/form-data)
  • Token obtained from login endpoint — store in app, send in every protected request
  • client_uuid for transactions: generate UUID v4 on the mobile device before sending — this prevents duplicate transactions when offline queue syncs
  • Offline sync: if device is offline, queue transactions locally with client_uuid — when online, send all queued transactions to POST /api/transactions — server ignores duplicates via unique client_uuid constraint
